# 其他中转站接入指南

本插件将 **Codex 本地用量、平台余额、平台账号今日消费**分开处理。不同中转站可能使用完全不同的接口，不能只更换域名或照搬企鹅 API 的认证方式。

通常让 Codex 按本文协助配置即可；完整密钥只在本地窗口中填写。

## 1. 先告诉 Codex 哪些信息

请准备平台名称、网址、只读接口文档链接；没有公开文档时，可提供脱敏后的请求及响应说明，删除密钥、Cookie 和账号隐私。接口说明应包含：

| 信息 | 为什么需要 |
| --- | --- |
| 请求方法与完整 HTTPS 路径 | 判断现有 `json_get` 是否可用 |
| 认证方式 | 例如请求头名称及前缀；模型 API Key 不一定能查询账号 |
| 成功标志与余额字段 | 例如嵌套字段路径；不凭字段名猜测 |
| 返回单位与换算规则 | 可能是货币、积分或原始额度，不自行换算 |
| 今日消费接口与时间规则 | 仅在需要实际消费时提供，需明确日期时区和时间边界 |
| 分页／汇总／限流规则 | 避免只取第一页或过度请求 |
| 模型价目表及有效期 | 仅在需要 Codex 费用估算时提供 |

“接口文档”就是平台说明如何用程序查询数据的资料。只有网站首页或控制台截图，通常不足以确定认证和字段。若暂时找不到，先启用 Codex Token，不要编造接口。

## 2. 普通余额：通常只改本地配置

条件是平台提供 **HTTPS GET、JSON 响应、固定字段路径、可由一个认证头完成的查询**。现有通用适配器名为 `json_get`。

编辑的是当前使用的私有 `config.local.json`，默认在**已安装插件根目录的 `.local` 中**，不是 GitHub 源码目录。先让 Codex 执行 `main.py init` 确认路径，保留已有平台，增加一个唯一 ID。

以下全部为**虚构结构示例**：`example.invalid` 无法用来查询真实余额，字段和币种也不是任何平台的约定。必须按真实文档替换。

```json
{
  "timezone_offset": "+08:00",
  "providers": {},
  "platforms": [
    {
      "id": "relay-a",
      "name": "我的中转站",
      "balance": {
        "adapter": "json_get",
        "url": "https://example.invalid/api/account/balance",
        "documentation_url": "https://example.invalid/docs/balance",
        "field": ["data", "balance"],
        "success_field": ["success"],
        "success_value": true,
        "unit": "USD",
        "divisor": "1",
        "headers": {},
        "auth": {
          "header": "Authorization",
          "prefix": "Bearer "
        }
      },
      "prices": {}
    }
  ],
  "bubble": {
    "manual": false,
    "display": "click",
    "platform_id": "relay-a",
    "cost_source": "estimate",
    "refresh_seconds": 60
  }
}
```

- `field`：余额在 JSON 中的路径，字符串表示对象键，非负整数表示数组索引。上例表示 `data.balance`。
- `success_field`／`success_value`：可选，按平台真实成功标志设置；没有此标志时不要照搬。
- `unit`：平台明确说明的单位，不能因为示例写 USD 就当作美元。
- `divisor`：显示值 = 原始余额 ÷ divisor。只有文档规定换算时才改变；默认 1。不支持通过该字段随意换汇。
- `headers`：仅放非敏感元数据。认证令牌、Cookie、密码不放这里，也不放 URL。
- `auth.header`／`auth.prefix`：按平台认证规则填写。公开无认证接口可省略整个 `auth`；其他接口用本地加密令牌。
- `documentation_url`：接口依据，保留可供核对的资料地址；如果只有私有说明，让 Codex 记录其可靠来源，且不要将私有资料发布。

保存非敏感设置后，在已安装插件根目录执行，或让 Codex 代为执行：

```powershell
python skills/codex-usage/scripts/main.py set-secret --platform relay-a
```

在本地窗口填写令牌。然后让 Codex 运行 `report` 做只读验证，并关闭／重新开启气泡。请求失败时先查认证、字段、单位和权限，不要绕过平台限制。

普通余额配置**不会自动获得账号今日消费**。这个示例保留默认估算模式；没有模型价格时费用显示未知，余额仍可使用。

### 可以直接发给 Codex

> 使用 $codex-usage 配置我的中转站余额。平台名【名称】，网址【网址】，接口文档【链接或脱敏说明】。请先阅读插件配置指南，核实请求方法、认证、成功标志、字段和单位。支持 HTTPS GET JSON 时用 json_get，仅合并修改当前生效的私有配置，保留其他平台。令牌用 set-secret 本地窗口输入，不要在聊天、命令参数或源码中放密钥。完成模拟验证后，在我本地已有凭证时做真实只读验证，分别说明结果。暂时只配置余额，不猜测费用。

## 3. 多个平台怎么配置

在 `platforms` 列表中增加对象，每个平台使用唯一 `id`。`bubble.platform_id` 选择气泡当前显示的平台；右键气泡也能切换。完整报告可显示多平台账号卡片。

每个平台分别输入令牌，即使两个平台的接口长得相似，也不能共用认证假设。企鹅专用 `penguin` 适配器只允许 `https://penguinapi.org`；其他 New API 站点同样要先确认接口，再使用 `json_get` 或新增自己的适配器。

今日 Token 是本机所有已识别 Codex 桌面端用量，**不会随余额平台筛选**。provider 映射用于 Codex 模型费用归属；不会将账号账单自动分配给本地会话。

## 4. 模型费用估算：改 providers 和 prices

这部分不需要修改统计源码。需要同时确认：

1. 本地 Codex 记录的实际 provider ID 与模型名，不能只看界面昵称猜测。
2. provider 对应哪个平台，由用户明确确认。
3. 模型每百万 Token 的输入、缓存读取、输出价格和币种。

在配置中建立映射，并给对应平台增加 `prices`。下例价格全部是**虚构演示值，不是实际价目表**；仅表示字段结构：

```json
{
  "providers": {
    "confirmed-provider-id": "relay-a"
  },
  "prices": {
    "exact-model-name": {
      "unit": "USD",
      "input": "1.00",
      "cached_input": "0.10",
      "output": "2.00"
    }
  }
}
```

注意：上面是**位置说明片段，不是可直接替换的完整配置**。`providers` 在顶层，`prices` 要放进 `platforms` 中 ID 为 `relay-a` 的对象；顶层 `prices` 不会用于计价。

若记录含缓存写入，还需真实 `cache_write_input` 价格，以及 `cache_write_in_input` 布尔值来说明是否已计入输入总量。推理输出已在输出总量中，不重复收费。非零用量缺少对应价格，费用即未知。

一个 provider 只能映射到一个平台。同一 provider 历史上切换过平台时，当前映射会作用于全部历史，不能据此声称还原了历史账单；建议为不同平台使用独立 provider ID。当前价目表也不能自动还原历史调价。

### 可以直接发给 Codex

> 使用 $codex-usage 配置【平台 ID】的 Codex 模型费用估算。我的 provider ID 是【已确认 ID】，价格来源是【平台价目表链接及有效期】。请核对本地实际模型名，将每百万 Token 的输入、缓存读取、输出以及必要的缓存写入价格写入本地配置。未知价格保留未知，不猜测、不把不同币种相加。保留已有平台、令牌和账号消费设置，并说明该价格能覆盖哪些模型与时间。若要气泡显示此估算，再将 cost_source 改为 estimate。

气泡切到 `platform` 模式后，模型图表仍需要这些价格才会显示估算费用。

## 5. 账号今日实际消费：其他平台需要适配源码

当前只有企鹅 API 实现此功能，读取当天账号汇总数据。对其他平台，单独设置 `cost_source: "platform"` 会提示未支持，**并不会根据 balance 配置自动查询账单**。

要接入新的平台，需要平台提供只读消费接口，并核实：

- 当天零点至查询时刻的时区、时间戳单位和边界；平台若按固定账单时区汇总，要明确标注。
- 返回的是当日消费、累计消费，还是某段时间的记录；汇总行不能与明细重复相加。
- 分页／数量上限，以及是否能取得完整当天数据；不完整时不能显示成完整总额。
- 金额、额度、退款／负数与换算规则；返回零和缺失字段必须区分。
- 认证权限、限流与单位规则；不使用账户余额差推算消费。

### 开发时改哪些文件

以下脚本路径均相对于 `plugins/codex-usage-pet/skills/codex-usage/`：

| 文件 | 需要改动的情况 |
| --- | --- |
| `scripts/spending.py` | 新增独立平台消费适配分支，明确当天范围、单位与汇总语义 |
| `scripts/balance.py` | 新增专用余额接口、共享认证／单位辅助函数或扩展请求能力时 |
| `scripts/credentials.py` | 确有多字段凭证等需求时；保持本地保护，不写明文配置 |
| `scripts/main.py` | 新配置字段需要验证或接入新的报告行为时 |
| `references/configuration.md` | 记录新增适配器的接口依据、参数及限制 |
| 仓库根目录 `tests/test_spending.py` 等 | 增加对应正常、零消费、异常及日期边界验证 |
| 当前生效的私有配置 | 启用已实现的适配器及所选平台，设置 cost_source |

优先保留现有按日缓存、限流、失败时旧数据状态及跨日清理逻辑。若缓存身份新增了与接口相关的设置，也要纳入失效规则。**不是把企鹅硬编码域名改成自己的域名**，那样会破坏已有平台并沿用未经确认的字段。

先在下载的源码中实现、验证并保留补丁，再备份私有配置后安装；不要只修改版本缓存，更新可能覆盖它。提交 GitHub 的是适配代码、脱敏文档和测试，绝不包含实际令牌或账单。

### 可以直接发给 Codex

> 请为 Codex 用量宠物接入【名称、网址】的账号今日实际消费，接口文档是【链接或脱敏说明】。我接受账号消费包含其他软件，Codex Token 和模型估算仍独立统计。先确认请求方法、认证、时区、当天边界、单位、分页和完整性；资料不足先指出阻塞，不猜接口、不用余额差代替。请在源码 spending.py 新增独立适配，必要时改 balance.py 和配置校验，更新配置参考，并验证正常／零值／认证失败／限流／字段变化／跨午夜等行为。用模拟数据验证后，再使用本地窗口保存的凭证做只读联调，明确两种验证结果。安装前备份私有配置和加密凭证，保留已有企鹅适配，不发布我的本地数据。

## 6. 接入完成后怎么核对

先用明确标注的模拟数据验证解析和错误状态，再用用户本地安全输入的凭证核对真实平台结果。金额比较要使用相同单位、日期、时区和统计范围，注意平台汇总延迟。

至少确认零余额能正常显示；认证失败、网络异常、限流和字段变化不会把旧余额变成最新；实际消费跨午夜后不会延用昨天的数字。重新开启后检查气泡显示的平台和费用模式。没有真实联调时，应明确写“只完成模拟验证”。

仅有接口首页、没有可用文档或必要权限时，可以先交付本地 Token 和界面，但不声称余额／消费已经接通。
